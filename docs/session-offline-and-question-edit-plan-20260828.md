# 场次下线与题库编辑改造计划

日期：2026-08-28  
状态：用户已批准实施及正式切换；后端与 2MB 迁移已上线，管理端等待用户 push main 发布，见 `session-offline-deployment-20260828.md`。  
范围：PocketBase 游戏后端、后台管理系统；答题页默认仅做兼容性回归，不增加列表过滤逻辑。

## 一、审批摘要

本次实现三个目标：

1. 场次永久下线：停止下发和玩家访问，结束未完成下发，完整保留已结算权益与后台记录。
2. 题目按引用关系锁定：线上场次使用中的题目不可修改或删除；解除线上引用后可原地修改，题目 ID 不变。
3. 管理端场次状态筛选：快速查看线上、草稿、已下线、全部场次。

用户已按本计划批准以下默认边界：

- **草稿引用不锁定修改，但阻止删除。** 否则复制场次为草稿后，题目会再次被锁住。
- **题目删除统一为软删除。** 从常规题库和选题列表移除，保留底层记录及历史关联；不提供物理删除。
- **本期不增加完整历史题面快照。** 保存题目修改前后配置的管理员审计；历史提交和结算不变，但后台旧场次关联的题面可能显示新内容。
- **默认不改答题页业务界面。** 后端过滤列表、拒绝访问，复用现有错误提示；不承诺已打开的信件等页面在下线瞬间自动消失。

批准本计划仅进入本地开发和隔离测试；不包含生产部署、生产数据修复、推送触发自动发布。

## 二、明确业务规则

### 2.1 场次状态与操作

沿用现有数据库枚举，避免仅为改文案新增状态或重建数据库：

| 数据状态 | 管理端名称 | 允许操作 | 玩家行为 |
| --- | --- | --- | --- |
| `draft` | 草稿 | 编辑、发布、复制、作废 | 不可下发，不可答题 |
| `published` | 线上 | 查看、下线、复制 | 按现有下发、时间窗和等级规则访问 |
| `archived` | 已下线 | 查看、复制 | 不再下发，列表不返回，旧链接与答题接口拒绝访问 |

“线上”指该场次版本已发布且未下线，不代表已经有玩家领取；即使尚未下发，也会锁定其引用的题目。草稿作废也进入终态，不能恢复发布。

下线后的原场次、关卡、线索和奖励规则不删除、不重建、不修改 ID。复制才创建新场次及子记录；复制结果为草稿，不自动发布或下发。原场次不能重新上线。

### 2.2 下线时对玩家记录的处理

下线命令在同一事务内完成：

1. 将目标场次设置为 `archived`。
2. 将该场次所有 `assigned`、`active` 下发记录转为现有的 `cancelled` 状态；不清除已经完成的关卡进度、提交和错误记录。
3. 已经 `completed` 的下发记录保持原状态；原本 `cancelled` 的记录不重复处理。
4. 保留经验流水、玩家经验余额、等级、奖品记录、奖品快照、领取信息和核销记录，不追溯重算，不扣回已发权益，也不为未完成内容补发奖励。
5. 记录操作者、原因、时间、受影响下发数量及状态变化，便于核查。

结束未完成下发同时释放现有“同一用户、同系列仅一个进行中下发”的限制，允许后续正常下发复制的新版本。

仅该下线场次从玩家列表隐藏；不要把其他线上场次下的全部 `cancelled` 历史一起隐藏。管理员单独撤回某个玩家的下发，仍沿用原有语义，不等于整场下线。

已发奖品继续从独立奖品接口获取，仍可展示领取信息、核销和按现有规则撤销核销。下线不删除通知；通知中的旧入口即使被点击，也必须经过后端访问拦截。公开 CDN 素材及已下载内容不在撤销范围。

### 2.3 题目修改、删除与引用规则

判断对象是具体题目 ID 的全部场次引用，不只检查正在查看的场次，也不要求场次已有玩家领取。

| 引用情况 | 原地修改 | 删除（软删除） |
| --- | --- | --- |
| 存在任意线上场次引用 | 禁止 | 禁止 |
| 无线上引用，但存在草稿引用 | 允许，草稿同步使用修改后内容 | 禁止，先解除草稿引用 |
| 仅被已下线场次引用 | 允许 | 允许，历史关联保留 |
| 完全没有引用 | 允许 | 允许 |

修改范围为当前题目编辑器已有字段：标题、题型、题干、提示、媒体、占位说明、选项及正确答案。题型或选项标识调整也属于修改，同样受上述锁定规则与现有数据校验约束。

普通保存更新原题目和答案记录，不更换题目 ID，不创建新题目版本，不修改引用它的场次关卡 ID。已发布且无线上引用的题目保存后仍保留已发布状态；草稿题目仍需显式发布。题目已软删除后只读，可复制成新题，不提供原记录恢复入口。

后端保存时重新计算引用，不能信任管理端打开编辑器时的旧结果。发布场次时也重新检查题目是否存在、已发布且未删除；两个操作在事务内串行确认，避免“发布后仍保存了旧编辑窗口”的绕过。

题目软删除复用现有 `archived` 状态及归档接口，管理端明确标为“删除（保留历史）/已移出题库”，避免与场次下线混淆。叙事内容的归档语义不随全局文案替换而改变。

复制已下线场次时仍引用原题目，不自动复制题库。如果包含已删除题目，草稿明确提示失效引用，必须替换并通过发布校验；不能静默跳过关卡或直接发布。

### 2.4 历史记录边界

保留的是旧提交值、当时判定结果、进度、经验和奖品结算，不承诺旧题面永久保持原样。

题目原地修改会影响所有仍引用该题目 ID 的后台场次展示。管理员查看旧记录时应提示“题面为当前配置，历史判定未重算”；尤其更换题型或选项标识后，旧提交值不得按新答案重新判定。

本期记录修改原因以及修改前后配置到仅管理员可访问的审计数据，不将正确答案或审计内容返回给玩家。审计用于追查，不等同于逐次下发的题面快照，也不倒推补造过去没有记录的题面版本。

如要求后台精确重现每位玩家当时的题面与选项，需另行审批快照方案，不纳入本期成本。

## 三、后端实施方案

### 3.1 下线、访问与结算

主要文件：

- `backend/pb_hooks/lib/admin.js`：将场次归档分流为专用下线逻辑；处理未完成下发与审计；下线终态检查；题目保存和软删除引用校验。
- `backend/pb_hooks/lib/gameplay.js`：增加玩家侧场次可访问性检查；保留后台读取进度的路径；开始、答题与下线操作保持事务一致性。
- `backend/pb_hooks/lib/api.js`：玩家列表过滤和玩家路由访问检查；管理员列表和详情继续返回旧记录。
- `backend/pb_hooks/lib/db.js`：按需要增加命令前置校验能力，修复幂等回执在下线后返回旧场次内容的问题，不改变其他命令的重试语义。

接口保持现有路径：

- `POST /admin/sessions/:id/archive`：改为完整下线语义；重复调用安全，可用于已归档记录的状态补齐。
- `GET /assignments`：只返回玩家可见的线上场次下发，后端过滤后再组装响应。
- `GET /assignments/:id`、`POST .../start`、`POST .../answers`、`GET .../narratives/:contentId`：统一阻止已下线场次访问。
- `GET /admin/assignments`、详情与提交记录：不套用玩家隐藏规则，后台仍可查询。
- 奖品与领取信息、核销相关接口不增加场次线上状态要求。

对有权限的玩家返回稳定错误码，例如 `SESSION_OFFLINE`，消息“该场次已下线”；未登录或访问其他玩家下发，继续遵守原认证与归属校验，避免泄露记录是否存在。现有答题页可以显示服务端消息。

关键实现要求：

- 不只依赖下发 `cancelled` 状态：已完成记录保持 `completed`，也必须根据场次状态隐藏和阻断访问。
- 下线与答题并发时，以事务提交顺序为准：先完成的有效答题结算保留；下线先完成则后续答题拒绝，不出现半关闭、半发奖。
- 开始/答题旧请求 ID 重放时，在返回幂等回执前检查当前访问权限，不能从历史回执重新返回已经下线的题面；原已完成结算仍保留，不重复发奖。
- 下线后不允许后台继续解锁线索、强制过关或延长旧下发；但不能误伤独立奖品的领取信息维护与核销。
- 后台详情不能因共用玩家详情函数而一起被拒绝。已取消下发的题目、提交与进度按管理员权限展示，不删除原数据。

### 3.2 题目引用信息与协议

管理端目录接口为题目补充引用摘要及可编辑、可删除信息，例如线上/草稿场次的 ID、标题和版本。服务端集中生成引用映射，避免每条题目重复扫描全部场次。

管理端据此展示锁定原因及关联场次入口；保存、软删除的后端检查仍是最终依据。引用冲突返回稳定业务错误，例如 `QUESTION_IN_USE`，并提供可理解的原因。

协议以 `backend/contracts/game.ts` 为源，使用现有同步脚本同步到管理端与答题页。优先只扩展管理员协议，保持玩家列表、详情、奖励响应和状态枚举兼容；生成的协议文件变化不等于答题页需要新增功能或重新设计列表。

本计划预计不需要新增数据库字段或重建集合。若实施发现确有新增索引等必要变更，使用新的增量迁移文件，不修改已执行迁移；出现额外数据模型需求时先说明范围，不擅自加入快照系统。

实施补充（2026-08-28 已获用户批准）：现有审计字段 `game_admin_audit_logs.safeDiff` 从 200,000 字节增至 2,000,000 字节，以完整保存题目修改前后配置。使用独立增量迁移，保留原字段和记录 ID，不新增字段、表或快照系统。

## 四、后台管理系统实施方案

主要修改 `src/game/ContentPages.tsx`、`src/game/OperationPages.tsx` 及必要的共享协议/请求辅助代码。

### 4.1 场次列表

- 增加“线上（默认）/草稿/已下线/全部”标签页，显示各状态数量。
- 保留表格分页，增加或保留标题搜索，状态切换时重置分页。
- “新版本”明确为“复制为新草稿”，复制成功后定位新草稿，避免默认线上标签下看不到新记录。
- 草稿发布后定位线上记录；下线成功后刷新列表、数量与题目引用信息。
- 下线确认展示场次名称/版本、当前已下发人数和未完成人数，要求填写原因，明确提示不可恢复、玩家入口消失、已发奖励保留；最终以服务端事务结果为准。
- 已下线记录仅查看和复制；草稿作废使用相应文案，不混同曾经上线的状态历史。

### 4.2 题库

- 将“发布后统一只读”改为“存在任何线上引用时只读”，已删除题目保持只读。
- 显示引用场次及锁定原因，允许跳转查看；草稿引用时提示修改会同步影响草稿。
- 删除入口说明为软删除；线上或草稿引用时禁用，并在后端再次校验。
- 正常题库及选题器默认不展示已删除题目，管理端保留查看已移出题库记录的入口。
- 对已有历史引用的修改提示历史题面影响并记录原因，保存后刷新引用与状态。
- 保留此前已完成的富文本配置提示和上传重命名，不重复重构这两项。

### 4.3 下发与旧记录

- 下发选择器继续只允许线上场次；复制、发布、下发仍是三个显式步骤，不自动选择用户。
- 旧下发在后台保留，通过所属场次状态区分“场次下线导致结束”和其他撤回记录，审计保存具体原因。
- 已完成用户的再次下发继续使用现有明确确认；无需重写奖励规则。
- 下线场次的进度干预按钮禁用，旧进度、提交、奖励及核销记录可查询。

## 五、答题页范围：默认不改业务代码

已确认当前待答/历史共用 `GET /assignments`，每 5 秒轮询；后端不返回，下次成功刷新后列表及数量自然更新，不新增前端状态过滤。

现有答题详情同样有轮询和错误兜底；后端拒绝后可显示“该场次已下线”，下一次提交也会被拒绝。网络离线、后台标签页节流和已发出的响应意味着不能承诺所有设备在固定 5 秒内清屏。

信件/祝福等叙事页面目前没有定时刷新；已加载内容可能继续显示，直到再次请求或刷新。重新请求旧链接时后端拒绝；公开媒体链接和用户已经保存的数据无法通过本次下线收回。

本期在答题页补充/运行回归测试，验证列表消失、旧链接报错和奖励继续显示；不增加列表隐藏规则、实时推送、强制跳转或新的下线专用页面。

若用户希望已打开的叙事也主动检查下线、清理相关缓存并返回列表，作为可选小项另行确认后加入，不作为核心后端规则的前提。

## 六、现有数据与发布边界

本轮未查询生产用户数或现有归档记录数量；不能以“没有正式用户”为前提设计，也不清空数据库。

旧 `archived` 原本只停止新下发；改造后将统一解释为永久下线。这是现有行为变化，需要在正式部署前：

1. 只读列出已归档场次，以及其 `assigned`、`active`、`completed` 数量，生成待处理清单，核实确切目标。
2. 由用户确认所有现存归档场次是否按本规则转为下线；未确认前不切换生产行为。若要保留旧归档可回顾语义，需要另行设计状态区分。
3. 完整备份并在隔离副本演练；不得直接复制运行中的单个 SQLite 文件充当完整备份。
4. 在维护窗口部署后端，并用可预览、幂等的维护流程补齐旧归档场次的未完成下发状态。复用经校验的下线逻辑与管理身份记录审计，不硬删、不重算结算。
5. 验证旧进行中下发不再占用同系列唯一约束，旧奖品仍可领取/核销，再发布管理端。

管理端仓库当前推送 `main` 会触发静态部署，但不会更新 PB 后端容器，因此实施阶段不擅自推送；正式发布需后端先具备新语义，再更新管理端。

回退优先采用保留新下线约束的前向修复。直接换回旧后端会让已下线的完成记录重新可见；直接恢复旧库又可能丢失新核销/答题记录，因此两者均不能作为无条件回退操作。

## 七、实施顺序与预计成本

1. **后端与回归先行**：下线事务、访问边界、旧回执校验、题目引用锁、审计与兼容协议，先补失败用例再实现。
2. **管理端接入**：场次标签页、下线确认、题目引用提示与编辑/软删除入口、旧记录只读规则。
3. **两端联调与交付**：隔离库完整流程、构建和协议检查、旧归档补齐演练、更新维护文档与发布清单。

按上述默认边界，预计约 2–3 个开发日，包含本地回归与联调；不包含生产发布等待、复杂存量数据异常处理、完整历史题面快照或主动清退已打开叙事页面。

## 八、验收清单

### 后端必须通过

- 未下发、已下发未开始、答一半、已完成、已撤回五类场景下线均符合规则。
- 下线后玩家待答和历史接口都无该场次，其他线上场次的记录不受影响。
- 旧详情、开始、答案、叙事链接均不能绕过下线；未授权玩家仍不能探测他人记录。
- 旧开始/答题请求 ID 重放不会泄露旧场次内容，不重复结算。
- 下线与答题并发、重复下线、事务失败回滚均无重复经验、重复奖品或半完成状态。
- 已获经验、等级、部分已答关卡奖励、完成奖励、领取信息和核销记录保持；未发权益不额外补发。
- 后台能查询旧进度和提交；不能继续推进下线场次，但奖品仍可领取信息维护和核销。
- 复制产生新草稿，原场次永远不能复活；未完成旧下发不阻塞同系列新下发。
- 题目被多个线上场次引用时，关闭其中一个仍不能修改；全部下线后才允许。
- 草稿引用允许修改、阻止删除；题目/答案保存后题目 ID 和旧关卡 ID 均不变。
- 题目软删除后不出现在正常选题中，旧记录关联仍在；含已删除题目的新草稿无法发布。
- 发布与改题/删除并发时不能绕过锁；直接调用接口与管理端限制一致。
- 已归档旧数据补齐可重复执行，不重复写入权益，不清除完成记录，清单统计与实际结果一致。
- 原有叙事归档规则单独保留测试，不能因场次下线测试变化而误改叙事全局语义。
