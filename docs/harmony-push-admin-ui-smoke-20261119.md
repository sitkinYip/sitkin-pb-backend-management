# 运营后台 Push 分类表单本机验收 · 2026-11-19

本轮使用当前真实 React/Ant Design 组件与本机合成 API。Vite 明确指向 localhost，未实现接口直接拒绝、不代理外部；浏览器连接策略限制为同源。没有访问或写入生产，没有修改业务源文件，也没有把模拟发送当作真实 Push 收发。

## 交互与请求核对

| 小点 | 实际观察与结果 |
| --- | --- |
| 默认用途 | 通知表单初始为公告，保留指定用户、当前所有有效用户、某场次参与者三种范围 |
| 场次动态 | 切换后范围被设置为场次，范围下拉只剩场次一项；选合成场次并填写标题正文可提交 |
| 提交后重置 | 成功后用途恢复公告，范围再次有三种选项 |
| 真实提交语义 | 捕获到一次通知 POST，body 的 messagePurpose=journey、target=session，并携带所选合成 sessionId |
| 推送范围保存 | 将合成白名单从玩家甲改为乙并填写原因，可保存；捕获一次 PATCH |
| 只读权益 | 保存体仅含 requestId、audience、playerIds、expectedRevision、reason，不含 subscriptionApproved、serverEnabled、testMode 等只读状态 |
| 运行状态提示 | 保存后总开关仍关闭、订阅分类仍未启用，前端没有因保存名单而打开服务端能力 |

以上表单操作使用 CUA 实际点选，提交体由本机 API 独立记录后只读复核。截图与原始合成请求保留在本机验收资料中，公开报告不包含账号口令、token、设备标识或私人内容。验收结束后仅关闭该次本机表单服务。

## 自动化覆盖边界

现有 48 个运营台测试与编译/构建已通过，但一次性源码副本中反转场次动态的范围条件后，这 48 个测试仍通过，说明原有用例未直接覆盖新增 Select 联动。本次交互 smoke 补充了上述实际证据；它不等于新增持续运行的浏览器回归测试。

后端独立验证场次动态必须关联场次、默认公告兼容、主动订阅及单独通知确认、取消后的投递约束。这里未验证生产部署、华为分类权益或邀请包通知送达。
