# 新场次编辑器与动态线索规则改造计划（修订版）

状态：历史方案，已被 2026-08-31 的[题目通用线索与已发布场次安全编辑实现说明](question-common-clues-and-live-settings-20260831.md)取代。本文曾在早期讨论中搁置，包含“发布后新增场次线索、旧场次退役”等未进入本次实现的设想，不应继续作为需求或发布依据。当前实现没有运行生产迁移、修改线上内容或执行旧场次退役。

## 1. 目标与原则

- 新方案创建的场次发布后，可以修正展示内容、编辑已有线索、追加线索，不要求下线、复制场次或重新下发。
- 按小关卡管理关卡线索；组合线索继续在组合场次的场次级配置中维护。
- 玩家下一次进入、查看历史或正常刷新数据时，根据既有进度看到最新应当可见的内容。
- 不批量补写历史解锁记录，不在读取接口写数据库，不重算经验、等级或奖品，不新增补弹窗机制。
- 对新方案创建的场次做局部编辑时，场次、关卡、线索 ID 保持不变；只有真正新增的线索获得新 ID，不因此生成新的业务版本。
- 场次已下线不可重新上线，玩家旧链接仍不可访问；本轮不改变既有下线与软删除规则。

### 1.1 基础内容保留、旧场次退役

- 保留题库题目、答案与原 ID；同时保留用户 / 管理员账号、等级定义、信件 / 祝福、奖品定义、通知和现有审计等基础内容，不顺手清库或删除 CDN 文件。
- 旧场次使用现有“下线 / 草稿作废”机制退役，不物理删除。其关卡、线索、下发、答卷、进度、经验流水、奖品领取和核销记录保持留存；只有按既有下线规则需要结束的待答 / 进行中下发会变为已取消，已完成记录保持原状态。
- 旧场次只读查看，不再编辑、发布、下发，也不提供复制旧场次 / 旧线索进入新编辑器的迁移入口。可以直接复用题库、信件与奖品等基础内容创建新场次。
- 退役对象以正式上线前复核的具体场次 ID 清单为准，在发布配置中持久记录，PB 写入 / 复制接口与管理页面一致执行，不仅依靠前端按钮限制。后续新场次下线后仍按新版本正常规则处理，不被误归入这份一次性旧场次清单。
- 退役清单用于明确对象和阻止旧场次重新进入编辑流程，不迁移旧场次 JSON，不新增长期新旧线索双轨模型；预计可沿用部署配置，不增加数据库字段。
- 旧场次的后台摘要、配置只读展示和原记录查看继续可用，但不做特殊旧配置继续编辑、草稿无损迁移或玩家继续体验的兼容工程。
- 2026-08-28 上次发布前快照为 31 个场次全部已下线，不能据此推定之后没有新建数据。正式退役需重新核对清单和备份，遇到不在确认范围的新场次先暂停确认。
- 本轮没有执行退役。计划获批后先在隔离环境验证；生产退役清单及切换窗口另行确认。

### 1.2 相比上一版删减的工作

不再承诺将旧草稿或已下线的旧场次复制、转换到新编辑器；不建立旧格式编辑适配，不对旧玩家开放退役内容，不补做旧场次的自动线索解锁数据。保留新场次今后需要的草稿保存、局部编辑、权限、手动解锁与历史回看测试，这些是正常功能，不是历史包袱。

## 2. 本轮开放范围

以下规则只针对新方案创建的场次。新草稿允许完整配置；发布后局部编辑；下线后只读，可按新方案复制为新草稿。一次性退役清单中的旧场次例外：只读，不复制迁移。

| 配置 | 已发布场次本轮规则 |
| --- | --- |
| 场次标题、说明 | 可原地修改 |
| 场次 BGM 模式及链接、背景模式及图片、标题显示设置 | 可原地修改 |
| 已有关卡的 BGM、背景、标题显示覆盖 | 可原地修改，关卡 ID 不变 |
| 已有线索的标题、正文、图片、视频 / 外链、入口提示及实际适用的展示文案 | 可原地修改，线索 ID 与解锁记录不变 |
| 普通线索的自动展示开关 | 可修改；不因此重播过去已发生的演出，正常后续触发沿用原行为 |
| 场次级组合线索的标题、富文本正文、确认按钮、底部说明 | 可原地修改，并允许追加 |
| 新增关卡线索 / 场次级线索 | 允许；创建时配置类型、触发方式和适用关联 |
| 已有线索类型、触发时机、所属场次、关联关卡、信件 / 祝福 ID | 本轮锁定；不是重新设计编辑器就开放全部字段 |
| 已有线上线索删除、停用、跨关卡移动、重排 | 本轮不做；未保存的新增编辑项可以取消，草稿继续允许移除 |
| 题目内容 / 答案、关卡增减顺序、换题、经验、惩罚、奖励规则、参与等级、自动下一题 | 本轮不开放；题库保留已有独立保护规则 |
| 通关演出模式、完成后继续入口 | 本轮保持线上只读；这是另一组流程 / 访问配置，不等于组合线索正文 |
| 信件 / 祝福自身正文与发布状态 | 不改变已有版本及删除策略；新增线索只能引用可用且已发布的内容 |

说明：这里的图片指场次 / 关卡背景与线索内容，不包括题库中的题面图片。新建线索可选现有全部类型，已有线索本轮只编辑展示内容。若后续需要修改已有线索的类型、触发规则、关联或删除，应再明确已可见内容如何处理。

## 3. 玩家可见性：读取时判断，不补写

### 3.1 判断规则

玩家场次详情接口先执行现有账号、归属、场次上线状态及下发状态检查，再计算可见线索：

| 线索条件 | 可见依据 |
| --- | --- |
| 开始场次 | 当前下发记录已有 startedAt |
| 完成指定小关卡 | 当前下发记录中该关卡已有 completedAt |
| 完成整个场次 | 当前下发记录已完成 |
| 管理员手动解锁 | 必须已有该用户本次下发对应的真实解锁记录 |

- 保留现有实际解锁记录带来的访问权限，包括管理员曾提前解锁的自动类型线索；与满足条件的线索合并，按线索 ID 去重、按现有顺序展示。
- 未开始的玩家不能因为场次配置存在就看到内容；已取消的下发不开放线索；已下线场次仍被入口拒绝。
- 玩家完成第 3 关后，再追加“完成第 3 关”线索，下次读取即可看到；尚未完成第 3 关的人仍看不到。
- 已通关者可以在仍在线的场次历史里看到后来追加的自动通关 / 已完成关卡线索；手动类型不会因为通关而自动开放。
- 普通线索和组合线索均使用这套判断。组合线索继续以整个场次完成为条件，不拆成各小关卡的重复配置。

### 3.2 数据与权限兼容

- 既有正常入场、答题、人工解锁仍沿用现有记录机制；本轮只取消“必须有旧解锁记录才可展示自动线索”的唯一依赖，不删除旧解锁表。
- GET 详情、历史查看和信件读取均不新增解锁记录，不调用入场、过关或发奖逻辑。
- 线索关联信件 / 祝福的访问鉴权使用同一个可见性判定，避免“能看到入口但打不开正文”，也不能靠猜 ID 绕过未解锁限制。
- 新场次引用剧情必须做有效性校验，不允许已移出内容。退役场次的原关联按原样留存并供后台只读查看，不开放旧玩家访问，也不为旧场次编写继续编辑的特殊兼容。
- 兼容现有响应中的 unlockedAt：已有记录使用真实时间；动态可见的线索采用稳定的可见生效时间（不早于条件满足时间和线索创建时间），不随每次查询变化、不伪造历史解锁记录。语义在代码和文档中说明。
- 管理员历史查看与玩家权限分开处理，不把管理员预览权限用于玩家判断，不将只读计算结果记成真实解锁审计。
- 批量读取线索、进度和解锁记录后在内存判断，避免对每条线索、每个玩家重复查询；不为追加线索扫描并写入所有历史下发。

## 4. PB 后端改造

### 4.1 独立局部更新

当前 saveSession 适用于草稿，会删除并重建关卡、线索和奖励规则。保留草稿工作流的边界，不通过取消 published 限制来开放线上整个保存接口。

新增或拆分以下职责的接口（具体路由名实施时按项目惯例确定）：

1. 更新场次展示：仅接受标题、说明与白名单展示字段。
2. 更新某关展示覆盖：校验关卡确属目标场次，只修改指定展示字段。
3. 更新某条线索内容：校验归属，只更新允许的字段，保留其类型、触发方式、关联和 ID。
4. 新增线索：校验所属场次、关卡、类型、触发条件、媒体链接和剧情引用，追加到现有顺序末尾。

实现约束：

- 不接收整份场次对象覆盖线上配置。未知字段、禁止修改字段和跨场次 ID 均明确拒绝。
- 嵌套 presentation 更新不能因默认值覆盖未编辑的 completionStyle 等锁定字段。
- 新增 / 修改 / 校验 / 审计在同一事务执行，复用请求幂等；失败不得部分保存或留下重复线索。
- 使用基于目标记录当前内容的编辑校验标识进行并发保护，不复用业务 revision 当编辑计数。旧页面保存不能覆盖另一个管理员已提交的新内容；冲突时保留输入并提示重新核对。
- 追加序号在事务内计算；与场次下线、剧情删除、其他追加并发时，重新校验最新状态。
- 新编辑器生成规范化字段；新场次局部更新仅改变明确提交的允许字段，不覆盖其他区块或引用。引用信件 / 祝福时校验类型和可用状态，不为退役线索提供编辑迁移。
- 审计记录操作人、对象、允许字段的前后变化与修改说明。线上编辑按本次保存填写一次简短原因，不为每个输入框单独确认。
- 本轮预计不新增集合、字段或迁移；如实施核对后确需数据库结构变更，先提出原因并重新确认，不自动扩大范围。

### 4.2 可见性重构

- 在 gameplay 中抽出线索可见性计算，供玩家详情和剧情鉴权复用。
- 保留正常游戏结算和手动解锁函数，不以重放 complete / start 实现追加可见。
- 服务返回最新内容；不承诺正在播放中的媒体或已经打开的弹窗立即替换，关闭重开 / 下次进入应一致。

### 4.3 退役边界

- 对发布时确认的退役 ID 清单，保存、发布、复制、下发、局部更新和追加线索入口统一拒绝；仍允许只读查询和既有下线操作的安全重试。
- 所有新建场次只能走新编辑器产出的规范结构；新场次的复制沿用新结构，不能通过传入旧场次 ID 绕过退役限制。
- 现有场次目录包含退役记录时仍能正常加载，不因旧字段不符合新建校验而使整个后台报错；这是基本可读性保障，不是迁移旧编辑配置。
- 退役清单、下线前后状态统计及校验摘要随发布材料留存；不通过清空进度、删除关系或修改题库 ID 达到退役目的。

## 5. 后台编辑器改造

沿用 React、Ant Design、现有提示组件和响应式样式，不更换 UI 框架或全站主题。根据 redesign-existing-projects 的审查结果，聚焦表单层级、渐进展开、状态提示与小屏操作，不扩展为全站视觉改版。

### 5.1 分组结构

```text
场次配置
├─ 基础展示：标题、说明、场次 BGM / 背景
├─ 小关卡：沿用现有题目与规则配置
│  ├─ 第 1 关 · 题目名称：展示覆盖、线索列表、添加线索
│  └─ 第 N 关 · 题目名称：展示覆盖、线索列表、添加线索
├─ 场次级线索
│  ├─ 开场 / 手动等场次级线索
│  └─ 组合线索 / 通关线索：仍在组合场次中配置
└─ 发奖与其他锁定规则：保留查看，草稿按原规则编辑
```

- 每关显示线索数量、类型和简短摘要，点击编辑才展开完整内容。
- 在某关旁添加，默认绑定该关并选择“完成本关”；无需再从全局关卡下拉列表中重复找一遍。
- 场次级组合线索创建时自动设置“完成整个场次”、不绑定单关，并保留玩家现有组合展示判定：多关卡场次、session_completed、无 sessionLevel、text 类型。
- 新场次按规范分组创建；退役旧场次使用只读详情，不加载进新线索编辑表单，不自动移动或转换旧组合配置。

### 5.2 按类型编辑

- 文字：标题、富文本正文及适用提示。
- 图片：图片列表与适用文案，复用现有上传 / 链接能力。
- 视频 / 外链：对应 URL 与适用文案。
- 信件 / 祝福：创建时选已发布内容，已有引用只读显示名称 / 版本，避免误认为可以修改共享正文。
- 组合线索：标题、富文本正文、确认按钮、底部说明；图片和视频按现有富文本语法插入正文。当前玩家组合组件不读取独立 imageUrls，不展示一个填写后无效的独立图片区。
- 保留并针对性显示 TextSyntaxHelp、示例、输入提示、必填校验与影响范围说明。不一次展开所有类型的字段。
- 新建时允许选择类型；新方案中已经发布的线索类型只读。切换新建 / 草稿类型时明确处理不适用字段；退役记录不参与这一流程。

### 5.3 保存与批量便利

- 线上基础展示、单关展示、单条线索独立保存，保存一项不提交其他未完成输入。
- 新建场次仍可多次保存草稿；未持久化的关卡使用稳定的表单标识绑定线索，保存时正确转换，移动关卡不串线索。线上关卡不重建、不移动。
- 支持复制新方案场次中的线索为待填写的新线索，并选择目标关卡；不是移动原线索，也不是从退役旧场次迁移配置。
- 提供为选中关卡批量准备线索编辑项的便利操作，默认只补缺少相应线索的关卡、不覆盖旧内容；保存前预览，未填完的项目不创建线上空白线索。
- 显示未保存、保存中、保存成功、冲突和失败状态；关闭编辑器 / 切换对象前保护未保存输入。独立保存刷新数据时不能冲掉其他编辑项。
- 清晰区分“新草稿可完整编辑 / 新线上场次局部编辑 / 新下线场次只读”和“旧场次只读退役”；退役详情提示从题库创建新场次，不显示旧场次复制入口。
- 保留现有线上 / 草稿 / 下线筛选，编辑保存后不错误跳回草稿列表。
- 桌面使用摘要列表与适度分栏；移动端单列编辑、操作区可见、长标题与 URL 合理换行，不产生整页横向滚动。

## 6. 改动面与执行顺序

工作主体仍是 PB 与管理后台；删减旧配置继续编辑和迁移工作，同时把答题页一处必要的展示兼容修正明确纳入计划。预计约 15–25 个文件量级，含测试、生成类型和文档，不是 15–25 个业务模块。

| 范围 | 主要涉及 |
| --- | --- |
| PB 后端 | lib/admin.js、api.js、gameplay.js；必要的局部更新 / 可见性辅助模块；复用内容引用保护 |
| 管理后台 | ContentPages.tsx、拆出的线索编辑组件及表单状态工具、guidance.ts、display-labels.ts、局部 admin.css |
| 答题页 | GamePlayPage.tsx 中自动展示候选的筛选及针对性测试；不负责计算访问权限或新增解锁状态 |
| 契约 | 如增加编辑校验标识等管理字段，从 backend/contracts/game.ts 统一生成两端副本，不手改生成文件；玩家现有必需字段不删除 |
| 测试 | 后端局部更新 / 动态可见性集成测试，管理端分组 / 组装 / 权限测试，答题页历史与组合展示兼容测试 |
| 发布材料 | 改造说明、回归记录、退役 ID 清单与只读 / 复制限制配置、PB 升级操作与版本记录 |

实施顺序：

1. 固化退役清单机制、新编辑字段白名单、组合线索判定和可见性规则；用隔离旧 / 新场次写核心测试。
2. 实现 PB 退役保护、局部写入、并发 / 幂等保护和只读可见性计算。
3. 改造新场次分组线索编辑与独立保存，再加新配置的复制和批量准备；旧场次保留只读详情。
4. 完成答题页自动展示的小兼容修改，联调桌面 / 手机、进行中 / 历史 / 信件访问。
5. 整理发布包及上线说明，交用户验收；生产另行审批退役对象、备份与切换。

### 6.1 答题页是否需要修改

核心的“可编辑、追加、下一次查看显示新版”由管理后台和 PB 完成，现有玩家详情接口与约 5 秒轮询可以继续使用。线索数据字段与组合展示形式保持兼容，不把权限判断搬到浏览器。

但计划明确包含一处小的答题页兼容修改，而不是承诺答题页零改动：

- 现有 GamePlayPage.tsx 在答题成功后，以“响应中的线索 ID 不在之前列表中”为依据加入展示队列。若管理员刚给更早的关卡追加了自动线索，玩家答下一题时可能把它误当作本次过关新解锁的线索弹出。
- 收紧为只对本次入场 / 当前关卡完成 / 本次整场完成对应的新可见线索执行既有自动展示；历史追加、普通轮询和回看不主动补弹。管理员提前解锁造成的既有访问权限仍由 PB 决定，前端不篡改可见列表。
- 线索列表仍展示 PB 返回的全部有权内容；本次修正只筛选演出队列，不影响列表、历史查看、答题结算或组合线索入口。
- 保留正常过关弹窗、通关组合演出及自动下一题行为；不新增广播、客户端解锁记录、额外游戏状态或新通知系统。
- 对同 ID 内容更新、BGM 切换、图片更新和关闭重开弹窗补测试；已打开的旧弹窗不要求强制中断替换。

因此按本计划完整落地时，需要发布管理后台、PB 后端和答题页；答题页只是小兼容修正。若实施发现需要除此之外的玩家运行时代码变更，先说明原因和范围再确认。

删减的是旧配置迁移及特殊继续编辑的工作，主要表单、保存和可见性功能仍需实现。按修订范围粗估约 3–4 个开发工作日量级，含测试、不含等待生产维护窗口；不是承诺工期。新增线索删除 / 类型或关联变更 / 结算规则编辑仍需另行估算。

## 7. 验收标准

### 数据与权限

以下新功能验收使用新方案场次。退役旧场次另验只读、不可发布 / 复制 / 下发与原始数据留存，不做旧配置继续编辑或玩家继续体验验收。

1. 修改场次展示后，场次、关卡、旧线索、奖励规则 ID 均不变；只有允许字段、目标记录更新时间和相应审计 / 命令回执变化。
2. 修改线索不改变原解锁记录；追加只产生新线索和必要的审计 / 命令回执，不批量改玩家数据。
3. 多次 GET 详情 / 历史 / 剧情接口前后，业务记录及解锁记录一致；可见时间稳定，内容不重复。
4. 未开始 / 部分完成 / 全部完成 / 取消 / 下线，以及开场 / 单关 / 整场 / 手动四种触发组合覆盖。
5. 历史无解锁记录但已满足自动条件者可见追加内容；未满足者及其他用户不能通过详情或剧情 URL 越权访问。
6. 新场次中的人工提前解锁保持可见；手动线索绝不因过关自动开放；新引用不接受已移出剧情内容。
7. 经验、玩家等级统计、答卷、奖品、领取与核销数据完全不变；正常后续答题只结算一次。
8. 伪造禁止字段、跨场次 ID、失效剧情引用被拒；下线后不能继续编辑。
9. 双人编辑冲突、重复追加请求、追加与下线 / 剧情删除 / 答题并发均不漏检；审计失败完整回滚。
10. 退役演练只改变目标场次状态及按现有下线语义取消的下发，题库及答案、账号、信件、奖品定义、经验与领取记录保持一致；名单外的新场次不受退役限制。

### 编辑与玩家体验

1. 10 个关卡可以分别添加线索，默认关卡和触发时机正确，不会串到其他关卡。
2. 已发布场次不必先下线；已有线索修改后，进行中玩家回看、已完成玩家历史查看均显示新版。
3. 组合线索仍只在场次级维护并按现有组合形式展示，标题 / 正文 / 按钮 / 底部说明均有效。
4. 复制和批量准备不覆盖原内容、不重复创建、不发布空白线索；草稿移动关卡后引用正确。
5. 失败、冲突、数据刷新、切换和关闭编辑器不会无提示丢失输入；修改一个区块不覆盖其他区块。
6. 单关 BGM / 背景覆盖与继承正确；历史新增内容可查阅，不因查看历史或轮询重播过关演出；在第 1 关已完成后追加自动线索，再答第 2 关，不误弹第 1 关线索，但本次第 2 关正常线索仍正常展示。
7. 桌面、390px 与 320px 手机验证线索列表、编辑表单、提示和操作区，无一字一行或整页横向溢出；键盘可操作。
8. 管理端、后端回归、共享契约检查、两端构建与相关答题页测试通过；验证仅使用隔离测试数据。

## 8. 上线边界

- 本计划获批后默认授权本地实施和隔离验收，不自动 commit / push、不操作真实玩家或内容、不立即更新生产容器。
- 上线前暂停配置 / 下发，重新核对旧场次清单并取得退役与维护窗口批准，做完整备份。按现有机制下线旧场次 / 作废旧草稿并核对结果，不能把不明的新数据自动归入退役清单。
- 部署顺序：PB 后端及退役保护配置 → 答题页小兼容更新 → 管理后台新编辑器；全部验收后再创建并下发正式新场次。答题页修改继续兼容原接口，不要求旧数据转换。
- 预计不需要数据库结构迁移；旧场次下线属于经批准的一次性状态处理，不等于结构迁移，也不等于物理删库。
- 不重发旧场次、不重置经验、不导入旧编辑配置。新正式场次由管理员在新编辑器中明确创建并下发，保留既有基础内容可复用。
- 新规则投入使用后，回退旧后端可能使依靠动态判定的线索不可见，也可能缺少退役保护；回退必须核对版本、清单与新产生的数据，禁止用旧库覆盖新业务数据。
