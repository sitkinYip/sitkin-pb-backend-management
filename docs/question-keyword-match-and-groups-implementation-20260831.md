# 题目关键词匹配与分组实现说明

日期：2026-08-31。本文记录本地实现和待发布边界；截至本文创建时没有连接生产、执行迁移、写入业务数据或部署前端。

## 行为约定

- 填空题默认继续使用现有精确匹配：答案列表中任意一项与用户回答归一化后相等即通过。
- 开启“模糊答案匹配”后，答案列表改为关键词列表。用户回答归一化后必须包含全部关键词，关键词顺序不限；只配置一项时只需包含该词。
- 关键词匹配沿用 NFKC、大小写、空白和标点归一化，不提供同义词或 AI 语义相似度判断。
- 选择题始终使用选项标识精确匹配，服务端拒绝为选择题开启关键词匹配。
- 空白/纯标点关键词和归一化后重复的关键词会被服务端拒绝，防止空关键词恒真或重复配置。
- 题目分组只进入管理员目录，不进入玩家题目 DTO。空分组统一显示和保存为“其他”。

## 数据兼容

新增私有空集合 `game_question_settings`：

| 字段 | 说明 |
| --- | --- |
| `question` | 唯一关联 `game_questions` |
| `answerMatchMode` | `exact` 或 `contains_all` |
| `groupName` | 最多 60 字符的后台分组名 |

迁移不回填旧题。没有设置记录的旧题按 `exact + 其他` 读取；运营打开旧题编辑并保存后会创建对应设置记录，因此可以趁题量较少逐题补齐。题目克隆会继承匹配模式和分组。

题面、答案和匹配模式继续受线上场次引用锁保护。分组不参与玩家展示或结算，可通过独立归类接口在题目被线上场次引用时修改，并写入管理员审计。

## 管理端

- 题目表单增加分组输入和模糊答案开关；开启后答案字段改名为“必须包含的关键词”。
- 题库增加分组列、判题方式列和分组筛选；标题、题目 ID 和分组均可搜索。
- 题目操作增加独立“归类”入口，适用于线上锁定和已移出题库的历史题。
- 场次选题下拉显示分组，并可按分组名搜索。

## 发布与回退边界

1. 使用现有只允许加法空集合的 verifier 审查 `1788176000_question_settings.js`；迁移后集合必须保持私有且为 0 条。
2. 先发布 PocketBase migration 与 hooks，验收旧题仍按精确模式答题、管理员目录显示“其他”。
3. 再发布管理端静态构建；玩家端公开协议没有变化，不需要功能发布。
4. 管理端上线后由运营逐题保存或使用“归类”入口回填；这一步属于生产业务写入，另行确认并记录。

应用代码需要回退时保留新增集合和迁移账本，旧 hooks 不读取该集合；禁止执行 migration down 或删除已经产生的设置记录。一旦新模式已用于真实答题，不使用旧数据库快照覆盖当前提交、经验和奖品数据，优先前向修复或仅回退应用代码。
