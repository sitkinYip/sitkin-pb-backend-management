# 信件 / 祝福软删除改造计划

状态：已获用户批准，2026-08-28 完成本地实施、验收及正式后端发布；管理前端等待用户 push 发布。见 [正式发布记录](narrative-soft-delete-deployment-20260828.md)。

## 1. 目标与规则

为“剧情内容 / 信件与祝福”增加与题库一致的软删除体验，允许只被已下线场次引用的内容移出内容库。

| 当前引用情况 | 是否允许删除 | 处理方式 |
| --- | --- | --- |
| 无场次引用 | 允许 | 填写原因并软删除 |
| 仅已下线场次引用 | 允许 | 保留原记录、ID、正文和历史关联 |
| 存在草稿引用 | 不允许 | 先从草稿移除或替换引用，或作废草稿 |
| 存在线上场次引用 | 不允许 | 先下线所有相关线上场次 |
| 已移出内容库 | 不重复删除 | 只读查看；需要再用时复制为新版本 |

判断按当前引用该具体内容 ID 的场次状态进行，不按玩家是否答完或是否实际读过信件判断。相同场次多处引用去重展示，但两种引用来源都必须检查：

1. 场次线索的 `narrative` 关联。
2. 场次通关后入口 `completionTarget.kind = narrative` 的 JSON ID。

软删除不修改任何场次状态、下发记录、答题进度、经验、奖品、领取信息或核销记录；不删除 CDN 图片、视频或音频。

## 2. 后端实现

- 在内容策略模块增加信件 / 祝福引用检查，复用现有场次状态分类与事务命令机制。
- 沿用 `POST /admin/narratives/:id/archive`，将新操作收紧为上述软删除规则，旧管理页面也不能绕过引用保护。
- 校验引用、更新状态、写入审计在同一事务内完成。被阻止时返回明确提示，包含关联场次名称及状态；失败不产生部分修改。
- 复用现有 `archived` 状态，不物理删除、不改 ID、不新增数据库状态；保留幂等重试能力。
- 删除原因必填。审计记录保留操作人、内容 ID、原因和状态变化。
- 新建 / 编辑场次不能新选已删除内容；发布校验覆盖线索和通关后入口，并明确提示“内容已移出，请替换或移除引用”，不能提示恢复发布旧内容。

### 复制旧场次

- 允许把带有已删除内容的旧场次复制为待修复草稿，不自动清空旧引用。
- 草稿编辑器显示原内容名称及“已移出，需替换”标记。
- 该草稿须替换或移除失效引用后才能保存和发布；不改动源场次。
- 若还需使用原信件，可查看其内容并复制为新的信件 / 祝福版本，发布后再替换场次引用。

### 既有归档数据兼容

旧实现允许归档内容仍被线上场次阅读。对已经存在的这类数据：

- 不自动断开关联、不下线场次，不改变玩家读取接口的旧行为。
- 在已移出内容列表中保留并标明引用情况；不把“已归档”误解为“从未被使用”。
- 新的删除操作及后续场次保存 / 发布按本计划检查；不增加恢复原版本发布的入口。

## 3. 管理页面

- “归档”操作调整为“删除（保留历史）”，使用确认弹窗并要求填写原因。
- 列表增加“正常内容 / 已移出（含历史归档） / 全部”筛选，默认只显示正常内容。
- 增加引用情况和删除限制提示，关联场次可跳转查看。无权限操作的原因保持可见，而不是只给一个灰色按钮。
- 管理端根据现有 catalog 的场次数据计算展示；后端在操作时独立检查，不信任前端判断。无需为此修改玩家接口或共享契约。
- 统一线索与完成入口两处选择器：不能新选已移出内容；历史已选值仍显示名称及失效标记，不能退化为裸 ID。
- 已移出内容只读，不提供恢复上线；允许复制新版本。
- 补充页面指引、删除风险说明及审计中文显示，沿用本次已完成的 Ant Design 响应式样式。

## 4. 验收标准

### 后端回归

- 无引用、仅已下线引用可删除；正文、ID、关联保持不变。
- 草稿 / 线上引用均阻止删除，线索和完成入口分别覆盖；多场次、同场次重复引用不漏检。
- 校验与删除失败不会修改内容或业务数据；重复请求保持幂等。
- 删除与场次保存 / 发布并发时，不出现引用已删除内容的新线上场次。
- 复制旧场次保留失效引用，未修复前不能保存 / 发布；替换后可正常保存和发布。
- 原有历史归档且仍被线上使用的内容继续可读；已下线场次的旧链接仍按现有规则拒绝访问。
- 经验、奖品、领取与核销数据不受影响。

### 管理端及浏览器

- 筛选、删除按钮、原因校验、引用跳转和复制提示正确。
- 删除后默认列表隐藏，已移出列表可查看原内容并复制。
- 两处选择器不提供新选已删除内容，旧值名称可见。
- 桌面与手机验证列表、删除弹窗、失效引用提示和场次编辑器。
- 管理前端测试、相关后端集成测试、契约检查及生产构建通过。

- 后端 `content-policy.js` 同时统计线索关联和完成入口 JSON 引用，按具体 ID 去重场次；`admin.js` 在事务内执行引用校验、软删除和审计。
