# 现有实例升级操作单：场次永久下线与题库编辑

本包仅适用于已运行 PocketBase 0.40.1 的 `questions-game-v1`，不是首次安装包，也不是执行生产变更的授权。正式操作前必须取得用户对停服、备份、增量迁移和镜像切换的明确批准。

## 发布内容与边界

- 镜像标签、架构和摘要以本包 `release.json` 为准，固定 Linux AMD64 / PocketBase 0.40.1。
- 包含完整 hooks、原始迁移及新增 `1787911200_expand_audit_diff.js`；保留之前的昵称/头像修复。
- 审计字段 `game_admin_audit_logs.safeDiff` 上限增至 2,000,000 字节，保留原集合、字段、题目、答案及历史记录 ID；不重算经验或奖品。
- 场次关闭、题库引用锁定及玩家入口限制属于业务逻辑更新。升级本身不关闭任何已发布场次，不取消线上场次下的进行中任务。
- 不含 Compose 模板、业务数据库、真实账号、凭据或前端构建。不得使用旧初始化操作单创建新库、重导内容或重建超级管理员。

## 正式切换前

1. 只读核实运行容器、镜像及实际 Compose 路径。当前目标为 `questions-game-v1`，配置 `/opt/1panel/apps/questions-game-v1/compose.yaml`，宿主数据目录 `/opt/1panel/apps/questions-game-v1/pb_data` 挂载 `/pb/pb_data`，仅绑定 `127.0.0.1:8090:8090`。若与实际不符，先停止操作并确认。
2. 只读统计旧 `archived` 场次及其下发状态，将具体清单交用户确认。新版本会立刻隐藏所有旧归档场次；有不应隐藏的旧场次时不得直接上线。没有旧归档场次则无需执行补齐工具。正式切换前再次核对，不能仅依赖早前统计。
3. 在独立发布目录解压，检查归档与内层 `SHA256SUMS`，再导入镜像；保留旧镜像、配置和历史发布包。不要把升级包解压到 `pb_data` 内或覆盖既有发布材料。
4. 先在隔离数据目录验证目标镜像、迁移与恢复，不把演练实例指向生产挂载。严禁两个 PB 实例同时打开同一生产数据目录。

## 经审批后的维护窗口

1. 暂停答题和管理操作，停止目标 PB 容器；不停止其他应用、Alist 或 OpenResty。
2. 创建新的私密备份目录，完整备份当前 `pb_data`、实际 Compose 及发布元信息，记录校验值；备份目录不得放在被备份目录内部或网站目录。不要只拷贝运行中的单个 `data.db` 文件。保留权限，复核备份可恢复。
3. 将备份解压至独立路径，用新镜像执行迁移；比较所有 `game_*` 业务记录、ID、经验、奖品和权限设置，确认只发生批准的审计容量调整。副本校验失败则不改生产配置，排查后再决定。
4. 只更新实际 Compose 中目标服务的镜像标签，保持原有数据挂载、回环端口、网络、安全配置和其他设置。用 `docker compose config` 校验，不能套用本项目首次安装的 18090 模板。
5. 在正式服务仍停止时，用新镜像及原数据挂载显式执行 `migrate up`，参数为 `--dir=/pb/pb_data --hooksDir=/pb/pb_hooks --migrationsDir=/pb/pb_migrations --automigrate=false`。不要执行 `migrate down`、`superuser upsert`、内容导入或初始化脚本。迁移失败立即停止后续切换，保留日志和数据核查。
6. 核实审计上限至少为 2,000,000，业务数据未变化，然后启动目标新容器。检查实际镜像、挂载、健康、端口和域名访问。
7. 仅当有已确认的旧归档目标时，用受控管理员身份调用补齐工具，将这些归档场次的 `assigned/active` 下发结束；保留完成状态与权益。不得把所有线上场次下发取消，也不直接用 SQL 更改业务状态。
8. 后端验收后，用户再 push 管理端，通过其 Action 发布静态页面。当前 Action 的接口探测不验证新业务版本；不能把探测通过当作后端更新完成。答题页本次无需单独功能发布。

## 验收与回退边界

- 在新镜像隔离实例测试完整答题、下线、题库编辑、经验和奖品流程。生产只做无副作用的版本/权限/列表核对；如需创建线上验收账号或执行测试写入，应另行批准。
- 扩容迁移不允许降回 200KB。回退应用代码也应保留更大的字段上限，不能为回退删掉审计记录。
- 新下线规则投入使用后，旧后端会重新暴露下线场次，因此不可无条件切回旧镜像。已有新的答题、经验或核销后，不得用旧库覆盖；先停写、保存现状并前向修复。
- 若首次启动前验证失败且尚无新业务写入，在核对数据完整性后可选择旧镜像恢复服务，但必须确认没有产生依赖新下线语义的操作。
- 本次确认不再需要维护后关闭专用 SSH 连接；不安装密钥、不修改密码、不开放公网维护端口。
