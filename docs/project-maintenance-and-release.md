# 项目维护与发布边界

本文是 `sitkin-pb-backend-management` 的长期维护入口。项目同时包含运营管理端、PocketBase 后端、数据库迁移、跨端协议和 1Panel 发布材料；“管理页面已部署”“后端已部署”“数据库已迁移”和“功能已激活”是不同状态。

当前线上版本、组件状态和最新正式记录统一从 [当前生产状态](current-production.md) 进入。带日期的 deployment 文档是审计快照，不承担“当前状态”职责。

## 项目组成

| 组成 | 位置 | 责任 |
| --- | --- | --- |
| 运营管理端 | `src/`、`tests/` | 玩家、等级、题库、叙事、场次、通知、下发、进度、奖品与核销界面 |
| PocketBase 后端 | `backend/pb_hooks/` | API、身份权限、内容约束、判题、经验、奖励、线索和审计 |
| 数据库定义 | `backend/pb_migrations/` | 集合、字段、索引、规则和增量迁移 |
| 共享协议 | `backend/contracts/game.ts` | 管理端与玩家端共用的接口类型和常量源 |
| 后端测试与打包 | `backend/tests/`、`backend/scripts/`、`backend/deploy/` | 隔离集成测试、镜像验证、恢复演练和 1Panel 发布材料 |
| 玩家端 | 相邻仓库 `questions-web` | 玩家答题、历史、线索和奖品展示，独立构建与发布 |

业务结算和访问控制必须由 PocketBase 服务端执行。管理页面可以改善操作体验，但不能成为权限、幂等或数据一致性的唯一防线。

专属等级头衔与自定义字段下发见 [使用与接入说明](extra-config.md)，原始表盘点见 [JSON 扩展配置调研](extra-config-and-player-titles-plan-20260908.md)。本地代码已实现，数据库与后端已于 2026-09-08 发布，两个前端待用户自行发布，功能未激活；普通展示新键可在首次能力部署后直接配置下发，业务约束仍由结构化模型负责。

## 发布对象相互独立

| 发布对象 | 触发与方式 | 数据库影响 |
| --- | --- | --- |
| 管理前端 | push `main`，Action 测试、构建并上传 `dist/` | 不更新 PocketBase 容器，不运行迁移 |
| 玩家前端 | `questions-web` 独立构建与发布 | 通常不直接写结构，但必须匹配 API 与行为语义 |
| PocketBase hooks / 镜像 | 目标架构隔离验证后，经批准切换 1Panel 服务 | 改变服务端行为，必须有备份和回退判断 |
| 数据库结构 | 新增量迁移随匹配后端版本发布 | 改变 schema 或规则，必须停写、恢复演练和允许差异清单 |
| 功能激活或首条新数据 | 两端兼容后由运营明确开启或写入 | 可能让旧客户端开始接收新协议，属于独立闸门 |

管理端 Action 中的 API 探测只说明基本可达和只读兼容，不证明 hooks 或迁移已经上线。健康接口返回 200、未登录接口返回 401，也不等于真实答题、经验、发奖或核销已经验收。

## 兼容矩阵决定发布顺序

涉及 API、新字段、新集合、一次性演出或新数据生产者时，发布计划至少回答：

| 运行组合 | 必须确认 |
| --- | --- |
| 旧玩家端 + 新后端，功能休眠 | 旧流程能否继续解析和运行 |
| 旧玩家端 + 新后端，功能激活 | 是否误播、丢字段、重复执行或错误导航 |
| 新玩家端 + 旧后端 | 字段缺失时是否安全回退 |
| 旧管理端 + 新后端 | 旧写入和读取是否仍合法 |
| 新管理端 + 旧后端 | 是否调用不存在的接口或写入不兼容数据 |
| 新管理端 + 新后端 + 旧玩家端 | 管理端是否会提前产生旧玩家端无法消费的数据 |

规则如下：

- 不写死后端、管理端和玩家端的顺序；从生产者、消费者和休眠条件推导。
- 后端先行只在新能力保持休眠时安全，且休眠条件必须可以只读验证，例如新集合持续为空。
- 新管理端若能产生新协议数据，必须晚于能安全消费这些数据的玩家端。
- 字段缺失、显式空数组和非空值必须有不同且稳定的语义。显式空结果是服务端权威结论时，客户端不能回退到旧差量猜测。
- 一次性效果、自动展示、跳转和奖励在状态转换事务中生成快照，并进入幂等回执；重试返回原结果，不读取后来变更的配置重新推导。

## 发布状态模型

所有实现说明、交接和发布记录按组件报告以下状态，并标为“已完成”“未完成”或“不在本次范围”：

1. 源码实现完成。
2. 本地和隔离测试通过。
3. 目标架构镜像验证通过。
4. 发布包生成并完成校验。
5. 已上传或导入，但未切换。
6. 数据库迁移完成。
7. 后端镜像已上线。
8. 玩家端已上线。
9. 管理端已上线。
10. 功能已激活或产生第一条生产数据。
11. 生产业务写入验收已执行，或明确未执行。

不得用“已经上线”笼统覆盖多个组件。数据库结构存在不等于功能已开放；后端上线不等于前台体验和后台入口已上线。

## 日常开发与验证

管理端本地默认连接 `https://api.sitkin.top`。本地页面写操作同样会修改真实数据，不能把线上库当作集成测试库。UI 与样式遵循 [管理后台 UI 工程与样式规范](admin-ui-engineering-standards.md)。

普通管理端改动至少运行：

```sh
pnpm test:admin
pnpm exec tsc --noEmit
pnpm check:contracts --admin-only
pnpm build
```

共享协议以 `backend/contracts/game.ts` 为源。两个仓库位于同级目录时运行 `node backend/scripts/sync-contracts.mjs`，随后验证两端；只能访问管理仓库时使用 `--admin-only`，并明确记录玩家端未验证。

修改 `backend/` 时，按 [后端说明](../backend/README.md) 构建隔离镜像并运行真实 PocketBase 集成测试、空库测试和旧库恢复副本演练。测试库必须临时创建，不能挂载生产 `pb_data`。新增结构使用新的迁移文件，不修改已经应用的迁移。

## 生产后端与数据库维护

真实生产只读检查、备份、迁移、镜像切换和恢复统一遵循 [PocketBase 后端迁移与生产发布安全规范](backend-release-safety.md)，普通受支持增量升级使用 [PocketBase 人工闸门发布程序](pocketbase-release-program.md)，并启用项目 Skill `questions-pocketbase-production`。

长期不变量：

- 只有用户明确批准本次目标、版本和维护窗口后才执行生产动作。
- 同一份 `pb_data` 同时只允许一个 PocketBase 实例打开，生产保持 `--automigrate=false`。
- 停写后完整备份数据目录、实际 Compose 和匹配版本材料，再将归档恢复到隔离位置验证。只复制运行中的 `data.db` 不算备份。
- preflight 不是锁；危险步骤前重检实际 image ID、Compose 哈希、挂载、端口、迁移账本和源码清单。
- 命令结果未知、迁移部分完成或哈希漂移时闭锁，不自动重试、不运行 down、不删除证据、不自动覆盖数据库。
- 产生新答题、经验、奖品、领取、核销或新功能数据后，不得用旧快照覆盖当前库；优先前向修复或只回退应用代码。
- 8090 保持回环，不停止或修改 1Panel 中无关的 OpenResty、AList 和其他应用。

`backend/deploy/1panel/README.md` 是 0.22.12 首次替换部署历史，不是普通增量升级必读文档。生产升级必须使用与当前 source、目标镜像、迁移列表和发布包完全匹配且标为待执行的版本专属操作单；已完成操作单不可复用。办公电脑受 Docker 白名单限制时，可由只读的手动 GitHub workflow 在审查过的 revision 出包，但 artifact 下载、摘要核对、隧道和每个生产闸门仍由人负责。

## 文档治理

文档分成三类：

- 长期规范：本文、UI 工程规范、后端发布安全规范。只在规则变化时更新，不硬编码“最近镜像”。
- 当前状态：`current-production.md`、根 README 和后端 README。组件发布、功能激活或当前基线变化后更新。
- 日期审计：`docs/*deployment-YYYYMMDD.md`。保留当时授权、哈希、备份、验收与未执行事项，后续上线不改写原事实。

生产发布收尾至少同步：当前状态指针、根和后端 README、`compose.production.yaml` 镜像、功能说明、日期 deployment 记录，以及版本专属操作单的“已完成 / 不可复用”状态。

## 权限、凭据与操作边界

- 未经明确要求，不 commit、不 push、不部署、不连接生产、不运行迁移、不导入或删除数据。
- 密码、超级管理员令牌、SSH 私钥、柜码、玩家答卷与领取信息不得进入聊天、前端变量、仓库或 CI 日志。
- 远程维护使用用户自己建立的专用 SSH control socket；密码只在用户终端输入，结束后关闭连接。
- AList/CDN 媒体不在 `pb_data` 备份范围内，需要独立保留和恢复策略。

项目开发说明见 [questions-admin-maintenance Skill](../.agents/skills/questions-admin-maintenance/SKILL.md)，生产运维说明见 [questions-pocketbase-production Skill](../.agents/skills/questions-pocketbase-production/SKILL.md)。
