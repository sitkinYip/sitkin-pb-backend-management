# 现有实例升级操作单：信件 / 祝福软删除

本包适用于已运行 PocketBase 0.40.1、且已完成场次下线与 2MB 审计升级的 `questions-game-v1`，不是首次安装包，也不是执行生产变更的授权。正式操作前必须取得用户对停服、备份和镜像切换的明确批准。

## 发布内容与边界

- 镜像标签、架构和摘要以本包 `release.json` 为准，固定 Linux AMD64 / PocketBase 0.40.1。
- 新增信件 / 祝福软删除引用保护，覆盖线索关联及通关后入口 JSON ID。无引用或仅下线场次引用时可删除，草稿 / 线上引用均阻止删除。
- 保存与发布场次不接受已移出内容；复制旧场次保留原引用供修复，修复后才能保存 / 发布。
- 已有归档内容仍按原玩家读取规则处理，不自动断开旧关联。删除要求原因、保留正文与 ID，审计和引用校验同事务执行。
- 包含完整 hooks 及两份既有迁移；保留昵称/头像修复、场次永久下线、题库引用锁和 2MB 审计能力。本次相对上一生产版本无新增迁移，不重新初始化数据库。
- 升级本身不删除任何内容、不关闭或重发场次、不取消下发，不改变经验、奖品、领取信息和核销记录。
- 不含 Compose 模板、业务数据库、真实账号、凭据或前端构建。不得使用旧初始化操作单创建新库、重导内容或重建超级管理员。

## 正式切换前

1. 只读核实运行容器、镜像及实际 Compose 路径。当前目标为 `questions-game-v1`，配置 `/opt/1panel/apps/questions-game-v1/compose.yaml`，宿主数据目录 `/opt/1panel/apps/questions-game-v1/pb_data` 挂载 `/pb/pb_data`，仅绑定 `127.0.0.1:8090:8090`。若与实际不符，先停止操作并确认。
2. 只读核实迁移账本已包含 `1787788800_game_schema.js` 和 `1787911200_expand_audit_diff.js`，审计 `safeDiff` 上限至少 2,000,000；否则停止并另行确认升级范围。统计场次、下发和历史归档剧情引用，保存汇总快照。不要运行旧归档补齐工具或修改状态。
3. 在独立发布目录解压，检查归档与内层 `SHA256SUMS`，再导入镜像；保留旧镜像、配置和历史发布包。不要把升级包解压到 `pb_data` 内或覆盖既有发布材料。
4. 先在隔离数据目录验证目标镜像及软删除规则，不把演练实例指向生产挂载。严禁两个 PB 实例同时打开同一生产数据目录。正式备份恢复核对在经批准的维护窗口内进行。

## 经审批后的维护窗口

1. 暂停答题和管理操作，停止目标 PB 容器；不停止其他应用、Alist 或 OpenResty。
2. 创建新的私密备份目录，完整备份当前 `pb_data`、实际 Compose 及发布元信息，记录校验值；备份目录不得放在被备份目录内部或网站目录。不要只拷贝运行中的单个 `data.db` 文件。保留权限，复核备份可恢复。
3. 将备份解压至独立路径，核实恢复完整性及新镜像兼容性，比较业务记录和权限设置。副本校验失败则不改生产配置，排查后再决定。生产只读核对不展示密码、答卷或领取信息。
4. 只更新实际 Compose 中目标服务的镜像标签，保持原有数据挂载、回环端口、网络、安全配置和其他设置。用 `docker compose config` 校验，不能套用本项目首次安装的 18090 模板。
5. 本次没有新增迁移，保持 `--automigrate=false`，不对生产运行迁移、`superuser upsert`、内容导入或初始化脚本。若实际运行版本或迁移账本不符合前置条件，应停止而不是自动补迁移。
6. 启动目标新容器，检查实际镜像、内嵌 hooks 校验值、挂载、健康、端口和域名访问。确认迁移账本、业务数据及设置没有发生升级引起的变化。
7. 不执行内容删除、场次下线、下发补齐或真实玩家答题验收。业务写入验证只使用独立测试实例；生产内容操作由管理员随后明确选择。
8. 后端验收后，用户再 push 管理端，通过其 Action 发布静态页面。当前 Action 的接口探测不验证新业务版本；不能把探测通过当作后端更新完成。答题页本次无需单独功能发布。

## 验收与回退边界

- 在新镜像隔离实例验证引用拦截、软删除、复制修复、经验和奖品保留。生产只做无副作用的版本/权限/数据核对；生产测试写入需另行批准。
- 本次无数据库结构变更。若切换前失败，优先维持原服务；不得通过降级迁移或重导旧库恢复。
- 旧镜像缺少剧情引用保护，新规则投入使用后不应无条件回退。尤其不能回退到场次下线升级之前的版本，避免重新暴露已下线场次。
- 已有新答题或核销后，禁止用旧备份覆盖当前业务数据；先停止写入并保存现状，再评估前向修复或仅回退应用代码。
- 本次确认不再需要维护后关闭专用 SSH 连接；不安装密钥、不修改密码、不开放公网维护端口。
